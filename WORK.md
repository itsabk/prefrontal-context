# WORK.md — execution context

What's being worked on, and what's planned next. Structure fits the project — phases, priorities, blocked work, references to detailed plans or specs where they genuinely help; don't impose a shape the work doesn't have. This file is current execution state, not an archive: when work completes, record what changed in `MEMORY.md` and rely on the implementation and git for history.

## Now

_Active work: what and why. When stopping with work in flight, leave one exact next action another agent could take without the conversation — plus, as context warrants, what "done" means for it, where the work stands (branch, uncommitted changes), and blockers with their cause. What the next agent actually needs, not a filled-in form._

## Next

_Planned work in rough priority order, at whatever detail is useful today — Next is for work the owner has asked for; mark entries that are your own proposal as awaiting the owner's decision. Longer-term possibilities the owner has acknowledged can sit at the end, plainly not commitments. Prune what no longer matters; don't let this section become a backlog museum._
