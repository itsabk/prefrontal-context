# MEMORY.md — the project as it stands

This file gives a capable agent the context to understand the project correctly: complete, relevant, current, and free of obsolete material. The requirement is not brevity — it is accuracy. Update it when reality changes; prune what becomes irrelevant or false; don't preserve superseded layers here (git has them). The sections below are defaults: reshape, rename, add, or drop them to fit the project. The italic prompts are template placeholders — replace them with real content as you verify it, and don't leave a section prompt-only.

## Direction — owner-governed

_The owner's vision, current direction, durable requirements, non-goals, and constraints — in the owner's words, from conversation or from documents the owner has named. Update only from new owner statements. If work drifts from this section, say so in conversation rather than editing it. Delete these italic prompts as you replace them with real content._

## State

_What exists and works right now — the durable facts a fresh agent would otherwise have to rediscover. Cite how you know (the command, test, or source) where it helps. Prune as things change._

## Architecture

_The non-obvious map: important paths and entry points, components, how the pieces fit, where things happen. Only what isn't obvious from reading the tree itself._

## Conventions and quirks

_How to work here: environment quirks, style expectations, gotchas, workarounds and the reasons they exist. Build, run, and test commands live in How to verify. Conventions the owner stated are owner-governed like Direction; conventions that grew from practice are yours to record and revise._

## How to verify

_Persistent knowledge about how this project proves itself: build, test, reproduce, review — what a competent agent would want to run when it matters. For research work this may be "how to reproduce the analysis"; rename or drop the section if it truly doesn't fit. Keep this as project knowledge, not a harness-side validation system._
